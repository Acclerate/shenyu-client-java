# ShenYu 2.6.1 ÷ Nacos 服务发现接入 divide 插件 — 全面复盘

> 时间跨度：2026-07-16（单日集中攻关）
> 目标：让已注册到 Nacos 的 `shenyu-http-demo`（8179 / 8189 两实例）以 **Nacos 服务发现** 方式成为 divide 插件 `/http-demo11` 选择器的上游，实现上游随 Nacos 实例上下线自动增删。

## 一、背景与诉求

仓库 `shenyu-client-java` 是 ShenYu Java 客户端源码。其中 `shenyu-http-demo` 是一个最小验证工程，用于验证：

1. **客户端把实例注册到 Nacos**（register，已先行完成）；
2. **divide 插件通过 Selector 的 Discovery Config（Type=nacos）** 去发现①注册进 Nacos 的服务实例，并作为网关上游。

本次复盘聚焦第 2 点从可行性分析、源码深挖、踩坑到最终打通的全过程。

|------|-----------|------|------|----------|
| Nacos Server | `nacos_server_232` | 宿主 8848 / 容器网 `nacos:8848` | 2.3.2 | **鉴权已关** `NACOS_AUTH_ENABLE=false`（实测匿名访问返回 200） |

**三条 Nacos 相关链路必须区分（全程最大误区来源）：**

1. **`shenyu-discovery-nacos`（admin 侧）**：订阅 Nacos 指定服务，把实例喂成 divide 上游 —— **本次目标路径**。
2. **`shenyu-registry-nacos`（客户端侧）**：demo 把自身实例注册进 Nacos —— 已用、已生效。
3. **`shenyu-sdk-*`（调用方侧）**：类似 Feign，让"调用方"发现"网关"地址 —— **与本项目无关**，官方 shenyu-sdk-nacos 文档解决的是这个，不解决 divide 上游问题。

**核心架构（监听方是 admin，不是网关）：**
```
demo(8179/8189) ──注册实例──▶ Nacos(shenyu-http-demo, DEFAULT_GROUP)
                                   │ NacosDiscoveryService 订阅
                                   ▼
        shenyu-admin (写 discovery_upstream) ──WebSocket 同步──▶ MySQL
                                   │
                                   ▼
        shenyu-bootstrap(divide 上游缓存) ──roundRobin 转发──▶ 8179/8189
```

## 三、关键机制（源码级，铁证）

### 3.1 注册进 Nacos 的服务名 = `props.name`
- `InstanceRegisterListener` 第 87 行：`instance.setAppName(discoveryConfig.getProps().getProperty("name"))`
- 经 `NacosInstanceRegisterRepository.persistInstance` → `namingService.registerInstance(appName, ...)`。
- 若 `props.name` 为空，默认 `spring.application.name`（`shenyu-http-demo`）。**绝不会自动等于 `registerPath`**。

### 3.2 推给 admin 的监听节点 listenerNode = `registerPath`
- `ClientDiscoveryConfigRefreshedEventListener` 第 92 行：`.listenerNode(shenyuDiscoveryConfig.getRegisterPath())`。
- admin 端 `NacosDiscoveryService` 以 `discovery_handler.listener_node` 作为 Nacos `serviceName` 订阅。

### 3.3 断链根因（全程第一坑）
ShenYu 设计意图：`registerPath` 即"要监听的 Nacos 服务名"（官方原文 *"registerPath can be understood as the name of the service to be monitored"*）。
原 yml 把 `registerPath` 设成 `/shenyu/register/http-demo`，而实例服务名是 `shenyu-http-demo`，二者不等 → **注册与监听指向两个不同服务名 → 客户端驱动路径必败**。

### 3.4 admin 的 syncData 不查 discovery_rel
`DiscoveryServiceImpl.syncData`（由网关 websocket 连接触发）通过 `selectorMapper.selectByDiscoveryId` + `discoveryHandlerMapper.selectBySelectorId` 间接关联。只对"discovery → handler → rel → **仍存在的** selector"执行 `fetchAll`/`createProxySelector → watch`。**selector 消失则整条发现链路断掉**。

### 3.5 字典 `shenyu_dict` 与运行时解耦
`type=discoveryMode` 的 nacos 字典 `dict_value` 默认 `groupName=SHENYU_GROUP`，**仅是 UI 新建时弹出的 props 模板占位符**。运行期 `NacosDiscoveryService.init()` 只读 `discovery` 表的 `props`/`server_list`，完全不回查字典。改字典不影响已在跑的 discovery 行（若想让 UI 默认变 DEFAULT_GROUP，需重启 admin，且仅影响"未来新建"）。

## 四、踩坑时间线与解决（9 个关键节点）

| # | 阶段 | 现象 / 问题 | 根因（已定位） | 解法 |
|---|------|------------|----------------|------|
| 1 | 可行性 | 客户端注册已 OK，但 divide 选择器无上游 | 缺 nacos 发现绑定 | 确认只需给 `/http-demo11` 建 type=nacos 绑定 |
| 2 | 鉴权 | 原计划把 nacos-client 2.0.4 鉴权 gRPC 列为高风险 | 用户澄清 `NACOS_AUTH_ENABLE=false` 已实测关闭 | 风险降级为验证项，props 不填 username/password |
| 3 | 深度分析 | 客户端驱动发现为何失败 | `registerPath≠props.name`，源码铁证断链 | 结论：客户端驱动不可靠，主推 admin 手动 |
| 4 | C1 实操 | UI 选 nacos 保存后 type 仍为空 | ① serverList 用 `nacos_server_232:8848`，下划线 `_` 致 gRPC `Illegal character in hostname //nacos_server_232:9848`，握手失败 200+ 次→回滚；② 2.6.1 discovery type 插件级锁定 | 改用无下划线别名 `nacos:8848`；放弃 C1 走 C3 |
| 5 | C3 执行 | DB 直改建 nacos discovery 对象 | 按计划 DB 直改 + 重启 admin | 落库 discovery/handler/rel |
| 6 | C3 卡点 | discovery_upstream 仍为空 | 绑定的 divide 选择器 `2077666398274277376` 在 admin 重启后**消失**（demo HTTP 重注册清掉） | 手动新建稳定 divide 选择器 `2079990020000000001` + rule |
| 7 | C3 触发 | 上游不触发 | admin 重启触发 demo 重注册，再次清选择器 | **改为只重启 gateway（非 admin）** 触发 syncData |
| 8 | 验证 | curl 10 次是否轮询 | 重启 gateway → `Subscribed to Nacos updates for key: shenyu-http-demo` → upstream 落 8179/8189 | ✅ 8189/8179 完美 roundRobin |
| 9 | 复盘修正 | pom/yml 注释归因错误 | 原注释写"gRPC 鉴权握手不兼容"，但鉴权已关 | 更正为"gRPC 版本不兼容（与鉴权无关）" |

**两个计划未预见的深坑：**
- **serverList 下划线 gRPC 坑**：容器名含 `_`，必须改用网络别名 `nacos:8848`。
- **divide 选择器消失**：admin 重启会触发 demo 重注册清掉 HTTP 建的选择器；改用"重启 gateway 不重启 admin" + 手动建稳定选择器绕过。

## 五、最终落地配方（可复用 ✅）

### 5.1 DB 落库数据（`shenyu_261`）
| 表 | id | 关键字段 |
|----|-----|---------|
| discovery | `2079990010000000001` | type=nacos, server_list=`nacos:8848`, props=`{"nacosNameSpace":"","groupName":"DEFAULT_GROUP"}`, level=0, plugin_name=divide |
| discovery_handler | `2079990010000000002` | listener_node=`shenyu-http-demo` |
| discovery_rel | `2079990010000000003` | selector_id=`2079990020000000001` |
| selector | `2079990020000000001` | plugin_id=5(divide), name=/http-demo11, handle=NULL |
| selector_condition | `2079990020000000002` | uri startsWith `/` `/http-demo11/` |
| rule | `2079990020000000003` | pathPattern `/http-demo11/**`, loadBalance=roundRobin |
| rule_condition | `2079990020000000004` | uri pathPattern `/` `/http-demo11/**` |

### 5.2 六条铁律
1. admin 连 Nacos 的 **serverList 必须用无下划线别名 `nacos:8848`**，禁用 `nacos_server_232:8848`。
2. discovery.props **必须显式 `groupName=DEFAULT_GROUP`**（默认 SHENYU_GROUP 订阅不到 demo 实例）。
3. handler.listener_node **必须 = Nacos 实际服务名**（`=props.name=shenyu-http-demo`）。
4. 需有 divide 选择器（`uri startsWith /contextPath/`）+ 规则（`uri pathPattern /contextPath/**`，`loadBalance=roundRobin`）；discovery 模式 selector.handle 可为 NULL。
5. **用重启 gateway 触发 syncData，不要重启 admin**（admin 重启触发 demo 重注册清选择器）。
6. discovery type 选 selector 级（level=0）即可，无需插件级。

## 九、经验沉淀（可复用）

1. **ShenYu Discovery 的监听方恒在 admin，网关零改动** —— 排查时第一时间看 admin 日志与依赖，而非网关。
2. **容器名下划线 `_` 是 Nacos gRPC 杀手** —— 任何 `xxx_xxx:port` 作 serverList 都会 `Illegal character in hostname`，一律改用无下划线网络别名。
3. **`registerPath` ≡ 被监听的 Nacos 服务名** —— 配客户端驱动发现时务必让 `registerPath = props.name`。
4. **2.6.1 下客户端推送的 discovery 配置不可靠落地** —— 选择器级 type 锁定、discovery_rel 不生成；稳定做法 = DB 直改 + 手动建稳定选择器 + 重启 gateway。
5. **字典 `shenyu_dict` 只是 UI 模板，与运行时解耦** —— 改字典不影响已在跑的 discovery 行，也别被默认值 SHENYU_GROUP 误导。
6. **回滚永远先 mysqldump** —— 本次备份 `backup_before_c3.sql`，可一键回滚。
